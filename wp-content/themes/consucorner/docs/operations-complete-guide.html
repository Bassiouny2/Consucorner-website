1. Start here

Your main screen is WooCommerce → Returns Almost everything — load an order, update fulfillment, review cancellation requests, advance returns, and issue Wallet/Direct refunds — happens from this one page plus the order edit screen.

ConsuCorner separates payment (WooCommerce order status) from physical progress (operations fulfillment) from after-delivery issues (returns & refunds). Operations owns fulfillment and return resolution. Vendors see status read-only. Customers see simplified labels — never raw Bosta codes.

Required permission: manage_woocommerce (Shop Manager or Administrator).

Geidea rule (critical): The website never auto-reverses Geidea payments. Wallet credits store balance. Direct records a WooCommerce refund but you must send money back via Geidea dashboard or bank transfer manually.

2. Three layers on every order

LayerWhat it tracksWhere you change itExample values
1. Payment Geidea, COD, wallet checkout Order edit → Status dropdown (top) Pending, Processing, Completed, Cancelled
2. Fulfillment Warehouse, packing, Bosta shipping, delivery — per vendor ConsuCorner operations fulfillment panel (order edit or Returns page) Confirmed → Preparing → Shipped → Out for delivery → Delivered
3. Return workflow Customer cancel until delivered; return after delivery/completed WooCommerce → Returns table → Actions column Requested → … → Received → Resolved
Common mistake Setting WooCommerce status to Completed does not update operations fulfillment by itself, but it does allow customer self-service returns. Prefer setting fulfillment to Delivered when the package arrives. Always check the fulfillment panel.

3. Who sees what

Customer (My Account)

Simplified fulfillment label only. Delivered shows as Completed. Bosta raw status is hidden. Can Cancel order while Confirmed → Out for delivery. Can Request return after Delivered or WooCommerce Completed. Emails confirm cancel/return requests.

Vendor (Dokan)

Read-only fulfillment + return labels. Sees Bosta status column on Orders list + tracking on detail. Sees earnings card (commission, return deductions, net payable). Cannot approve returns, cancellations, or refunds.

Operations (you)

Full fulfillment control, Bosta mapping, cancellation approve/reject, return workflow, Wallet/Direct refunds. Vendor Ledger for monthly payout reporting.

Multi-vendor orders

  • One parent WooCommerce order; fulfillment tracked per vendor on that parent order.
  • Summary line shows the slowest vendor status (bottleneck).
  • One Bosta shipment per order — when Bosta updates, all vendors sync to the mapped status.
  • Customer cancel unlocks until Delivered; return unlocks when Delivered (or WooCommerce Completed), or ops creates a manual return.

6. Bosta auto-sync

When Bosta updates bosta_status or bosta_state_code on the order (webhook or manual meta), ConsuCorner maps it to fulfillment for every vendor. Sync only moves forward — never downgrades.

Bosta state / status textMaps to fulfillment
Created, Pickup requested (codes 10–11)Confirmed
Pickup / warehouse prep codes (21–22)Preparing
Received at warehouse (text or code ≥10 with warehouse text)Shipped ← treated as shipped, not preparing
Picked up, In transit, between hubs (20, 30–31)Shipped
Out for delivery (41)Out for delivery
Delivered (45–46)Delivered
Terminated / Returned (48, 100, 101, 104)Cancelled (if not already past shipped)

Look for order notes: "Bosta sync updated vendor #… fulfillment from … to …". Bosta fields on the order:

  • bosta_tracking_number — shown to customer for tracking
  • bosta_status — human-readable Bosta label (vendors + ops only)
  • bosta_state_code — numeric code used for mapping
When Bosta webhook is delayed Once you confirm handover to Bosta, you may manually set fulfillment to Shipped on the fulfillment panel. Bosta will catch up later without downgrading.

7. Manual fulfillment updates

From order edit

  1. WooCommerce → Orders → [order]
  2. Scroll to ConsuCorner operations fulfillment
  3. For each vendor: choose status, optional note → Save fulfillment

From Returns page

  1. WooCommerce → Returns → Load order
  2. Use vendor cards under Vendor fulfillment
Cannot cancel after Shipped If the order already shipped, do not try to set fulfillment to Cancelled. Use the return workflow or handle delivery failure via Bosta support.

8. Cancellation requests (before shipment)

Customers request cancellation from My Account → Orders while fulfillment is Confirmed, Preparing, Shipped, or Out for delivery (not Delivered / Completed). Operations must approve or reject — cancellation is never automatic. Submitting a request emails the customer, ops, and vendors.

Customer requests→ Ops reviews→ Approved or Rejected

What the customer can cancel

  • Whole order — all remaining line items
  • Specific items — item-level partial cancellation (qty picker)

How operations processes a cancellation

  1. WooCommerce → Returns (pending badge includes cancellation requests)
  2. Load the order → scroll to Cancellation requests
  3. Review items, reason, and current fulfillment
  4. Optional: add a note in the text field
  5. Click Approve cancellation or Reject

What happens on approve

Request typeSystem actionRefund / payment
Whole order WooCommerce order → Cancelled; vendor fulfillment → Cancelled Process Geidea/bank refund manually outside WordPress (or wallet credit via separate process if agreed)
Partial (items) WooCommerce partial refund created (refund_payment = false); affected vendor fulfillment → Cancelled Same — no automatic Geidea reversal
Cancellation ≠ Wallet/Direct return refund Approving a cancellation records the cancel/refund in WooCommerce but does not run the Returns page Wallet/Direct flow. For post-shipment returns, use the return workflow in Section 9.

Vendors see a Cancellation badge in Dokan when a request is pending or resolved. They are notified by email when customers submit and when you approve/reject.

9. Return workflow (after shipment)

Wallet / Direct buttons appear only when return status is Received Advance the return through every step in the Actions column before refunding.

Create a manual return (operations)

  1. Returns → Load order → confirm Return eligible badge
  2. Under Create manual return request, tick line items and quantities
  3. Enter reason and notes → Create return request(s)
  4. Multi-vendor orders create one RMA per vendor
  5. Find the row in the Returns table (filter by internal order ID if needed)
  6. Advance workflow to Received, then refund (Section 10)
Click workflow buttons one at a time Wait for the green success notice after each click before the next step.

10. Wallet vs Direct refunds

After return status = Received, click one of:

Wallet (store credit)

  • Credits customer ConsuCorner wallet immediately
  • Customer uses balance on next purchase
  • Optional shipping deduction (EGP amount subtracted before credit)
  • Reduces vendor Dokan earnings / net payable
  • Does not touch Geidea

Best for: Standard returns where store credit is acceptable.

Direct (manual)

  • Creates WooCommerce refund for bookkeeping
  • refund_payment = false — Geidea not auto-reversed
  • You refund customer via Geidea dashboard or bank transfer
  • Same vendor earning adjustment as Wallet

Best for: Customer paid Geidea and wants money back to card/bank.

Refund steps (both routes)

  1. Confirm return is Received
  2. Click Wallet or Direct
  3. Confirm the popup
  4. Answer Restock items? (Yes/No)
  5. Wallet only: enter shipping deduction (0 if none)
  6. Verify Resolution column shows Wallet or Direct (manual)
  7. Check order notes for audit trail
  8. Direct only: complete Geidea/bank refund outside WordPress
Never double-refund Do not refund the same line item via Returns + Wallet meta box + manual WC refund. One resolution per return request.

Edge-case refunds (avoid if possible)

MethodWhereWhen
Wallet Operations meta box Order edit → sidebar Partial wallet credit without RMA — blocked if item already on open return
WooCommerce Refund UI Order edit → line items refund Bookkeeping only; skips return workflow — avoid duplicating Returns resolution

11. Vendor Ledger (finance team)

WooCommerce → Vendor Ledger reports what each vendor earned after commission and return deductions. Vendor bank payouts are manual (contract/bank transfer) — this screen is for visibility and CSV export.

13. Step-by-step playbooks

A — New order, ship via Bosta

  1. Confirm payment (Geidea/COD) in order status
  2. Notify vendors / set fulfillment Confirmed per vendor
  3. Pack → set Preparing or wait for Bosta
  4. Create Bosta shipment; confirm tracking on order
  5. Let Bosta sync to Shipped → Delivered
  6. Customer sees tracking + status in My Account

B — Customer wants to cancel before shipping

  1. Customer submits cancellation from My Account
  2. Returns → Load order → Cancellation requests
  3. Approve or reject with note
  4. If approved: process Geidea/bank refund manually if payment was captured
  5. Confirm order cancelled and vendors notified

C — Customer return after delivery (self-service)

  1. Customer submits return from My Account (Delivered / Completed)
  2. Returns table → advance workflow to Received
  3. Wallet or Direct as per policy

D — Customer wants to cancel while shipped / out for delivery

  1. Customer submits Cancel order from My Account
  2. Ops reviews on Returns → Approve or Reject
  3. If approved: WC cancel/refund recorded; process Geidea/bank offline if needed

15. Printable checklists

Daily fulfillment

  • ☐ New paid orders → Confirmed per vendor
  • ☐ Packed orders → Bosta shipment + tracking
  • ☐ Pending cancellation requests reviewed
  • ☐ Pending return requests in Returns table reviewed
  • ☐ Bosta delivered statuses match fulfillment panel

Return refund

  • ☐ Fulfillment Shipped+ (or manual return created for Completed)
  • ☐ Return workflow → Received
  • ☐ Wallet or Direct chosen
  • ☐ Restock yes/no confirmed
  • ☐ Resolution column + order note verified
  • ☐ Direct: Geidea/bank refund done outside WP

Cancellation approve

  • ☐ Fulfillment still pre-ship (Confirmed / Preparing)
  • ☐ Items and qty reviewed
  • ☐ Approve or Reject with note
  • ☐ Payment refund arranged manually if Geidea paid
