Returns & Refunds — Operations Guide

How to resolve return requests as Wallet or Direct (manual) refund on ConsuCorner.

Version 2.9.4 · Complete Guide (recommended) · Fulfillment

Quick answer

Wallet / Direct buttons appear only after the return workflow reaches Received Go to WooCommerce → Returns, find the return request row, advance the workflow until status is Received, then click Wallet or Direct in the Actions column.

You cannot mark an order as refunded from the fulfillment panel alone. Refunds are always tied to a return request (Dokan RMA) and resolved on the Returns page — unless you use the legacy wallet meta box for edge cases.

Before you start

  • Permission: You need manage_woocommerce (Shop Manager / Administrator).
  • Fulfillment: Customer self-service returns need Delivered (or WooCommerce Completed). Ops manual returns need Shipped or later (see Fulfillment Guide).
  • Return request: A Dokan RMA request must exist — submitted by the customer or created manually by operations.
  • Geidea: Neither Wallet nor Direct auto-reverses Geidea. You handle money movement separately (bank portal / Geidea dashboard) when using Direct.

Return workflow (required before refund)

Why don't I see Wallet / Direct? The return is not at Received yet, or it was already resolved (column shows Wallet or Direct (manual) in Resolution).
Dokan status vs operations workflow Several operations steps (Approved, Return in transit, Received) map to the same Dokan RMA status (processing) in the background. That is normal. Operations workflow status in the Status column is what matters — not the Dokan filter dropdown values.
Click workflow buttons one at a time After each click (Reviewing, Approved, etc.), wait for the green success notice and the table to refresh before clicking the next button. Clicking too fast can hit a stale row.

Step-by-step: resolve a return (Wallet or Direct)

Path A — Customer already submitted a return

  1. Open WooCommerce → Returns in wp-admin.
  2. Find the return row (filter by order ID, vendor, or date). Click the order link if you need order context.
  3. In Actions, click workflow buttons in order: Reviewing → Approved → Return in transit → Received.
  4. After Received, Wallet and Direct buttons appear.
  5. Click your chosen route (see comparison below).
  6. Confirm the popup message.
  7. Answer Restock items? (Yes/No) — whether returned quantity goes back to stock.
  8. Wallet only: Enter shipping deduction amount (EGP to subtract from refund, or 0).
  9. Success message appears; Resolution column shows Wallet or Direct; status becomes Resolved.
  10. Check order notes on the order for audit trail.

Path B — Operations creates the return first

  1. WooCommerce → Returns → Operations order workflow.
  2. Enter order number → Load order.
  3. Confirm fulfillment is Return eligible (Shipped or later).
  4. Under Create manual return request, tick line items, set qty, reason, notes → Create return request(s).
  5. One RMA request is created per vendor if items span multiple vendors.
  6. Scroll to the Returns table below. In the Order # filter field, enter the internal ID (e.g. 5662, not always the long display number) → click Filter.
  7. Continue from Path A step 3.

Wallet vs Direct — which to choose?

Wallet

Use when: Customer should receive store credit in their ConsuCorner wallet for a future purchase.

  • Credits cc_add_to_custom_wallet() immediately
  • Customer sees balance in My Account → Wallet
  • Reduces vendor Dokan earnings for monthly payouts
  • Optional shipping cost deduction before credit
  • Does not touch Geidea / bank

Best for: Standard returns where you prefer wallet credit over cash back.

Direct (manual)

Use when: Customer was paid via Geidea/bank and you will refund offline (bank transfer, Geidea portal, cash).

  • Records a WooCommerce refund for bookkeeping
  • refund_payment = false — gateway is not auto-reversed
  • Reduces vendor Dokan earnings same as Wallet
  • Creates WC refund ID on the order
  • You must send money to customer manually outside WordPress

Best for: Cash/Geidea refunds after you have already processed payment reversal in Geidea dashboard.

Never expect automatic Geidea reversal Direct only records the refund in WooCommerce. Operations must still process the actual money return through Geidea or bank transfer.

Other ways to refund (without Returns Wallet/Direct)

These are for edge cases only. Prefer the Returns page flow above so vendor ledger and return status stay in sync.

MethodWhereWhen to use
Wallet Operations meta box Orders → edit order → sidebar Wallet Operations: Partial Refund & Exchange Partial wallet credit without a formal RMA, or legacy workflows. Blocked if the same items are already on an open/resolved RMA.
WooCommerce Refund Orders → edit order → Refund section at bottom of line items Manual WC bookkeeping only. Does not run the return workflow. Avoid duplicating items already refunded via Returns.
Do not double-refund Never refund the same line item twice (Returns + wallet meta box, or Returns + WC refund).

Finding return requests

  • WooCommerce → Returns — master list with filters (date, vendor, status, order ID)
  • WooCommerce → Orders — Returns column shows Open / Resolved
  • Order edit screen — yellow notice + link to Returns page
  • Pending badge on WooCommerce menu when returns await review

Lookup tip: use display order number in Load order (e.g. 13566249) or internal ID (e.g. 5662). For the returns table filter, use the internal WooCommerce ID in the Order # field — the long display number may not match the database filter.

Operations checklist (printable)

  1. ☐ Confirm order fulfillment is Shipped or later
  2. ☐ Confirm return request exists (customer or manual)
  3. ☐ Reviewing → Approved → Return in transit → Received
  4. ☐ Choose Wallet (store credit) or Direct (offline money + WC record)
  5. ☐ Confirm restock yes/no
  6. ☐ Wallet: enter shipping deduction if applicable
  7. ☐ Verify Resolution column + order note
  8. ☐ Direct only: process Geidea/bank refund outside WordPress
  9. ☐ Notify customer if needed
