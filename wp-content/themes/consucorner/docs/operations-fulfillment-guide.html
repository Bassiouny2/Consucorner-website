1. Overview

ConsuCorner uses a dedicated operations fulfillment workflow that is separate from WooCommerce payment status. Operations owns fulfillment from the moment an order is placed until it is delivered (or cancelled before shipping).

Key principle The WooCommerce Status dropdown (Processing, Completed, On hold, etc.) tracks payment. The ConsuCorner operations fulfillment panel tracks physical order progress per vendor. Do not confuse the two.

Fulfillment status controls:

  • What customers see in My Account → Order History
  • When the Request return button becomes available
  • What vendors see as read-only status in their Dokan dashboard
  • Operations notes and audit trail on the order

2. Two status systems — side by side

WooCommerce status Operations fulfillment
Purpose Payment & accounting (Geidea, COD, etc.) Warehouse, packing, Bosta shipping, delivery
Who changes it Payment gateway, finance, or admin manually Operations team (or auto-sync from Bosta)
Where to find it Top of order edit screen — Status dropdown ConsuCorner operations fulfillment panel below order details
Typical values Pending, Processing, Completed, Cancelled Confirmed → Preparing → Shipped → Out for delivery → Delivered
Drives returns? No (legacy Dokan setting may still say Completed — ignore for gating) Yes — customer cancel until Out for delivery; return after Delivered / Completed
Common mistake Changing WooCommerce status to Completed does not update operations fulfillment by itself, but it does allow customer self-service returns. Prefer setting fulfillment to Delivered when the package arrives.

4. Fulfillment statuses — meaning & actions

Confirmed → Preparing → Shipped → Out for delivery → Delivered

↳ Cancelled is available from Confirmed or Preparing only (before shipment).

Status Meaning Typical trigger Ops action
Confirmed Starting status for every new order. Order is acknowledged and ready to pick & pack. Automatic when order is created Verify payment (Geidea/COD). Notify vendors if needed. Start allocation.
Preparing Items being picked, packed, or waiting at warehouse. Manual ops update, or Bosta pickup-stage codes (21–22) Confirm all line items from each vendor are ready. Create Bosta shipment when packed.
Shipped Handed to Bosta / in transit. Returns become eligible. Manual ops update, or Bosta in-transit statuses Verify tracking number on order. Customer can still cancel until Delivered; returns unlock after Delivered.
Out for delivery Courier is on the last-mile route to the customer. Bosta Out for delivery (state 41 or matching text) Monitor Bosta tracking. Prepare for delivery issues.
Delivered Customer received the package. Final fulfillment state. Bosta delivered (state 45/46) Close fulfillment loop. Returns still allowed if within policy window.
Cancelled Order fulfilment stopped before completion (stock issue, customer cancel, Bosta terminated). Manual ops (early stages), or Bosta terminated/returned codes Coordinate refund separately (wallet/manual — never auto-reverse Geidea).
Return eligibility badge On the fulfillment panel, Return eligible appears when at least one vendor on the order is at Shipped, Out for delivery, or Delivered.

5. Allowed status transitions

Operations can only move fulfillment one step forward at a time (except Bosta auto-sync, which can jump multiple steps forward). You cannot skip backwards.

Current status Can move to
ConfirmedPreparing, Cancelled
PreparingShipped, Cancelled
ShippedOut for delivery, Delivered
Out for deliveryDelivered
DeliveredFinal — no further moves
CancelledFinal — no further moves
Cannot cancel after shipment If an order is already Shipped or later, you cannot set fulfillment to Cancelled through the normal workflow. Handle delivery failures via Bosta support and returns/refund process instead.

6. Multi-vendor orders

When a customer buys from multiple vendors in one checkout, there is one parent WooCommerce order with multiple vendor line items. Fulfillment is tracked per vendor on that parent order.

What you will see

  • One card per vendor in the fulfillment panel (vendor name + current status)
  • Each vendor can be at a different fulfillment stage
  • The summary line Current fulfillment shows the lowest status among all vendors (bottleneck view)

Best practice

  1. Update each vendor as their items are confirmed, packed, and included in the shipment
  2. When the whole package ships via Bosta, all vendors typically move to Shipped together (Bosta sync does this automatically)
  3. If one vendor is delayed, their card can stay on Preparing while others advance — customer cancel stays available until delivered lines are past OFD; return unlocks when Delivered / Completed
One Bosta shipment per order Bosta tracking is stored on the parent order. There is no separate Bosta status per vendor. When Bosta updates, all vendors on the order are synced to the mapped fulfillment status.

7. Bosta auto-sync

When the Bosta plugin receives a webhook (or Bosta metadata is saved on an order), ConsuCorner automatically maps the Bosta shipment state to operations fulfillment for every vendor on the order.

When sync runs

  • Automatically when Bosta updates bosta_status or bosta_state_code on the order
  • When you open the order edit screen or load the order on the Returns page (backfill for existing orders)

Bosta → fulfillment mapping

Bosta state / status Maps to fulfillment
Created, Pickup requested (codes 10–11) Confirmed
Pickup / warehouse prep (codes 21–22) Preparing
Received at warehouse (text or warehouse handling) Shipped
Picked up, In transit between Hubs (codes 20, 30–31) Shipped
Out for delivery (code 41 or matching text) Out for delivery
Delivered (codes 45–46) Delivered
Terminated / Returned / Cancelled (codes 48, 100, 101, 104) Cancelled (only if not already shipped+)

Sync rules operations must know

  • Forward only — Bosta never downgrades fulfillment. If you manually set a higher status, a later Bosta update will not pull it back.
  • Multi-step jumps — Bosta can move from Confirmed directly to Shipped in one webhook (system walks through intermediate steps internally).
  • Order notes — Look for notes like "Bosta sync updated vendor #… fulfillment from … to …"
  • UI indicator — When Bosta data exists, the panel shows Bosta shipment: [status] and Auto-syncs to [fulfillment]

Bosta fields on the order

Field Description
bosta_tracking_numberTracking ID — shown to customer in My Account
bosta_statusHuman-readable status text from Bosta
bosta_state_codeNumeric state used for mapping
bosta_delivery_dateSet automatically when delivered (state 45)

8. Manual fulfillment updates

Use manual updates when Bosta is not connected yet, for corrections, or to reflect vendor-specific progress before the shipment is created.

From order edit screen

  1. Open WooCommerce → Orders → [order]
  2. Scroll to ConsuCorner operations fulfillment
  3. For each vendor card: choose new status, add optional note, click Save fulfillment
  4. Changes save immediately (no page reload) and appear in order notes

From Returns page

  1. WooCommerce → Returns
  2. Enter order ID → Load order
  3. Use the same vendor cards under Vendor fulfillment

When to use manual vs Bosta

Situation Recommended approach
Bosta shipment created & tracking active Let Bosta auto-sync handle Shipped → Delivered. Only intervene if Bosta is wrong.
Vendor confirmed but not yet in Bosta Manually set Confirmed or Preparing
One vendor delayed in multi-vendor order Update that vendor's card individually
Bosta webhook delayed Manually advance to Shipped once you confirm handover to Bosta
Need to correct a mistake You can only move forward one step. Contact dev/admin if a status was set too high by error.

9. Order numbers — display vs internal ID

Customers see a display order number (e.g. 13566249). Operations screens also show the internal WooCommerce ID in parentheses (e.g. 5662).

Format Display number = {minutes}{orderID}{seconds} from order creation time.
Example: order ID 5662 created at 14:45:30 → display number 45566230 (minutes 45 + ID 5662 + seconds 30).

Both numbers work in the Returns page lookup field. Use whichever the customer or Bosta provides.

10. Link to customer returns & refunds

Fulfillment is the gate for customer-initiated returns:

  • Before Delivered — customer can Cancel order (Confirmed → Out for delivery)
  • Delivered or WooCommerce Completed — customer can submit a Request return
Return eligible badge vs summary line The panel may show Current fulfillment: Confirmed together with a Return eligible badge on multi-vendor orders. That happens when at least one vendor is Shipped+ even if others are still Confirmed. Returns unlock when any vendor reaches Shipped or later.

After fulfillment — what operations does next

Returns and refunds are not set on the fulfillment panel. Use WooCommerce → Returns:

  1. Customer submits return or ops creates one manually (Load order → tick items → Create return request)
  2. Advance return workflow: Reviewing → Approved → Return in transit → Received
  3. Click Wallet (store credit) or Direct (manual WC refund + offline Geidea/bank)

Full refund steps: Returns & Refunds Guide.

Geidea payments Fulfillment and returns never auto-reverse Geidea charges. Refunds are processed via wallet credit or recorded manual refund only.

11. Full order lifecycle (fulfillment → return → refund)

Operations touches the same order in three layers. Keep them in order:

Phase Where Goal Ends when
1. Payment WooCommerce order status Geidea/COD confirmed Processing / Completed
2. Fulfillment ConsuCorner operations fulfillment panel Pack & ship via Bosta Delivered (or Cancelled before ship)
3. Return workflow WooCommerce → Returns table Review & receive returned goods Received
4. Refund resolution Returns → Wallet or Direct Credit customer / record refund Resolved
Confirmed → Shipped → Return requested → Received → Wallet / Direct

13. What vendors see (read-only)

Vendors cannot change fulfillment or return workflow statuses. They see read-only labels plus a Bosta status column on the Dokan Orders list (React DataViews) and Bosta tracking on order detail.

  • Dokan → Orders — ConsuCorner status column
  • Order detail — ConsuCorner operations status panel
  • RMA requests — notice that operations manages status

If a vendor reports a wrong status, operations updates it in WordPress — not the vendor dashboard.

14. Daily operations workflows

Morning — new orders

  • Review new WooCommerce orders (payment confirmed)
  • Verify fulfillment shows Confirmed for each vendor (starting status)
  • Move to Preparing once packing starts
  • Flag unpaid / failed Geidea orders — do not advance fulfillment

Midday — warehouse & Bosta

  • Update vendors to Preparing as items are packed
  • Create Bosta shipments from the Bosta plugin
  • Confirm bosta_tracking_number appears on the order
  • Let Bosta sync move status to Shipped — or set manually if webhook is delayed

Delivery monitoring

  • Watch Bosta for Out for delivery and Delivered
  • Confirm fulfillment matches Bosta on the order edit screen
  • Respond to customer "where is my order" using Bosta tracking link

Exceptions

  • Customer cancel before ship → set vendor fulfillment to Cancelled
  • Bosta terminated → check if fulfillment moved to Cancelled; process refund separately
  • Partial vendor delay → update only that vendor's card
  • Return requests → handle on Returns page after fulfillment is Shipped+

15. Troubleshooting

Problem Likely cause What to do
Fulfillment stuck on Confirmed but Bosta shows in transit Bosta meta missing or webhook not received Check order for bosta_status / bosta_state_code. Reload order edit page to trigger backfill. If meta exists but status wrong, set Shipped manually.
Customer cannot see Request return Order not Delivered / Completed yet (or RMA warranty missing) If still in transit, customer should Cancel order. If delivered, set fulfillment to Delivered or confirm WC status Completed, then hard-refresh My Account.
Cannot change status — error about transition Trying to skip a step or go backwards Move one step at a time: Confirmed → Preparing → Shipped, etc.
Returns page says order not found Wrong ID format Try display number and internal ID. Copy from order edit screen.
Vendor sees different status than operations Vendor sub-order vs parent order Always update fulfillment on the parent marketplace order.

16. Do / Don't rules

Do
  • Use operations fulfillment as the source of truth for shipping progress
  • Let Bosta auto-sync handle in-transit and delivered updates when possible
  • Update each vendor card on multi-vendor orders when needed
  • Add notes when manually changing status (reason, ticket ID)
  • Check Bosta tracking before telling a customer their order shipped
  • Process refunds only via Wallet or Direct manual on Returns page
Don't
  • Don't use WooCommerce Completed as a substitute for fulfillment
  • Don't tell customers returns are open based on payment status alone
  • Don't ask vendors to change fulfillment — they are read-only
  • Don't auto-refund Geidea from the theme or fulfillment screens
  • Don't cancel fulfillment after the order is already shipped (use returns process)
  • Don't edit Bosta plugin files — report integration issues to tech team
